# 四智能体、工具权限与运行时边界

日期：2026-09-05  
对应版本：v341

## 总体规则

Codex、Claude Code 和 Minis 是三个通用主智能体。它们可以独立工作，也可以参加三智能体协作。手机操作智能体是第四个独立智能体，专门操作 Android UI，目前只接受用户从其页面直接发起的任务。

三个主智能体共享三套终端、Shizuku system-shell、Android 共享存储和真实浏览器。共享能力不意味着共享会话：每个智能体仍维护自己的模型配置、聊天历史、运行状态和工具语义。

## Codex

主要角色：软件工程、仓库维护、终端执行、调试、测试、构建和发布。

模型入口：OpenAI 账户授权；Responses 兼容第三方提供商。  
会话控制：支持按会话切换提供商、模型和推理强度。  
独立模式：完整支持。  
协作角色：可以担任总调度，也可以作为成员。  
历史记录：Codex线程与消息由宿主同步、恢复和管理。

可用能力包括本地 shell、Ubuntu、Alpine、system-shell、共享浏览器、文件编辑、补丁应用、Git与GitHub、网络检索、图像读取、skills、plugins和MCP连接器。具体外部连接器取决于用户安装和授权。

Codex CLI 在首次配置后由权限管理页安装。APK记录目标版本和下载逻辑，但不把用户已经安装的CLI目录当作构建产物覆盖。

## Claude Code

主要角色：代码分析、复杂工具编排、文档和资料处理、通用长任务。

模型入口：Anthropic官方接口、阿里云Coding Plan、自定义Anthropic兼容网关。  
独立模式：完整支持。  
协作角色：可以担任总调度，也可以作为成员。  
历史记录：独立会话存储，与协作记录分区展示。

Claude通过AnyClaw工具层使用本地终端、Ubuntu、Alpine、system-shell和minis_browser。工具层还可以提供搜索、网页抓取、HTTP、GitHub和文件操作；需要凭据的服务在未配置时会明确返回缺少凭据。

Android本地直接执行Claude脚本时需要Node解释器入口，应用宿主已按该方式启动，避免依赖标准Linux的/usr/bin/env路径。

## OpenMinis

主要角色：移动原生通用助手、模型提供商接入、真实浏览器和轻量运行时任务。

模型入口：OpenMinis自带提供商管理。  
独立模式：完整支持。  
协作角色：可以担任总调度，也可以作为成员。  
历史记录：使用Minis自己的会话管理，同时把协作运行映射到统一看板。

Minis原生拥有Alpine PRoot环境和可视WebView浏览器。口袋大龙虾通过宿主工具桥向它补充Android本地终端与Ubuntu，并通过多进程Shizuku支持提供系统链路。跨智能体文件应写入Android真实共享存储；Alpine内部伪路径不能被当作其他进程可见的共享目录。

## 手机操作智能体

主要角色：观察屏幕并操作Android应用。

模型入口：独立视觉模型管理。  
协议：AutoGLM Native、GUI Plus Native、Generic JSON。  
运行模式：主屏幕、隔离虚拟屏幕。  
协作角色：不参加三智能体协作。  
调用边界：v341不向Codex、Claude或Minis暴露启动接口，只允许用户手动发起。

动作集合包括Launch、Tap、Type、Swipe、Back、Home、Wait、Double Tap、Long Press、Take over和Finish。模型接收当前截图与任务上下文，宿主负责动作解析、坐标换算、文本粘贴、键盘处理、应用启动、截图重试、错误诊断和步数限制。

Take over只用于技术上必须由用户输入密码、一次性验证码、CAPTCHA或生物识别的情况。普通输入、发送、确认、安装或授权不会仅因动作类别被判定为敏感。

## 共享终端

### Android本地终端

身份是应用UID。HOME和PREFIX位于应用私有目录。它可以访问应用安装的Node、Python、Git、curl、ripgrep和其他命令，也可以在授权后访问共享存储。适合检查宿主、处理用户文件和调用Android兼容二进制。

### Ubuntu

Ubuntu 24.04通过ubuntu-shell进入，用户空间内通常为root，但这只是PRoot环境的root，不等于Android系统root。它提供apt、Python、Git、curl和标准Linux目录布局。Android共享目录通过绑定挂载访问。

### Alpine

Alpine来自OpenMinis运行时，也在PRoot中以用户空间root运行。它轻量、启动快，适合简单命令和Minis原生工具。需要跨智能体交换的文件必须确认落在Android真实共享目录。

### system-shell

system-shell通过Shizuku运行，身份为Android shell UID 2000。它可以执行系统允许shell用户执行的包管理查询、设备属性、系统服务和文件操作。它不具备root权限，不能绕过SELinux或应用私有目录边界。

## 共享浏览器

浏览器服务位于独立:minis进程并监听本地回环桥。三个主智能体可以执行导航、前进、后退、刷新、截图、点击、输入、正文提取、DOM查询、JavaScript、悬停、滚动、标签页和Cookie操作。

标签页拥有稳定tabId。需要接续其他智能体页面时必须读取标签列表并显式指定tabId。宿主串行处理显式标签动作，降低并行冲突。用户可以从任意主智能体页面打开共享浏览器并接管。

## 三智能体协作消息关系

用户只与当前总调度直接交互。总调度可以直接回复、澄清或委派。成员不会直接把最终消息发送给用户，而是把结构化结果返回总调度。总调度负责判断成员是否真实完成、是否需要返工，以及何时收口。

每一轮可以选择零个、一个或两个成员。下一轮可以重新判断，不继承上一轮必须委派的结论。长任务状态必须落入宿主持久化记录，不能只依赖内存中的进程句柄。成员失败、超时或进程重启时，总调度能够看到终态并决定重试、缩小任务或向用户说明。

## 权限边界

基础网络、前台服务、唤醒锁和启动恢复由APK声明。共享存储需要用户授权。Shizuku需要Shizuku服务运行并对当前包授权。悬浮窗只影响主屏幕手机操作时的进度浮层。相机、麦克风、相册、联系人、日历和位置只在对应功能需要时请求。

API密钥和账户令牌属于用户私有数据，保存在应用私有目录。诊断导出应隐藏密钥、Authorization头和完整令牌。三个主智能体可以访问用户明确提供给其环境的凭据，但不应把凭据写入仓库或协作共享目录。

## 并发与冲突

三个智能体可以同时运行不同任务。不同终端进程可以并行，但同时修改同一文件需要明确所有权或使用临时文件加原子替换。浏览器可以并行使用不同标签；多个智能体同时操作同一标签可能互相改变页面。system-shell命令由Android系统执行，修改同一系统状态时需要由总调度协调。

共享工作区默认关闭。任务只需要独立分析时，成员直接返回文本。共同编辑文件时，总调度指定唯一目录、文件边界和合并责任，避免三个智能体同时覆盖同一文件。

## 可验证性

权限中心显示Codex安装、Shizuku授权和system-shell状态。终端命令返回退出码和输出，但聊天页面默认只展示智能体评论与最终回复。浏览器工具返回URL、tabId、页面信息和截图路径。协作看板保存委派消息、成员回复和总调度结论。手机操作任务保存模式、displayId、模型、步骤、动作、错误和终态。

这些信号让用户可以区分模型没有执行、工具调用失败、前端没有刷新和任务已经完成但尚未显示等不同问题。
