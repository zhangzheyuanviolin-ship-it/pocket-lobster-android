# v363 Claude 真实模型压缩与任务续接修复候选

此版本是待真机验收的 test 通讯包，不替换 v362 的已验证稳定标签。Codex、Claude CLI、Minis 和手机操作智能体均不升级。APK 仅由 GitHub Actions 构建，本机只做测试。

## 真实事故与根因

2026-10-06，Claude UI 会话 claude-code-20261006_071122 的兼容压缩失败。原生压缩工作会话 5e949e9a-cc08-4ae6-ab74-91948c1d39f0 使用 MiniMax-M3，却调用 Read、Bash、搜索和 TodoWrite，最终回答历史请求而不是输出摘要，被旧校验丢弃。

根因一：压缩复用了普通助手的 CLI 入口、MCP、权限与附加提示词。禁止工具只是低优先级自然语言要求，没有真正禁用工具，也没有隔离历史中的指令。

根因二：现有运行参数为 contextWindowTokens=524288、autoCompactWindowTokens=514000、maxOutputTokens=512000。旧预算算法预留几乎整个窗口，约14K输入便被判超过约11K的剩余预算。模型上下文并没有用满。

## 修复边界

新增独立只读压缩 worker；使用原配置的模型、API 地址及认证，仅隔离工具、MCP、系统指令、hooks、settings、技能和会话持久化。正常任务仍保留原有工具。每次压缩最多三次自动重试，超时有界，全文请求失败时以无损连续分片交给同一真实模型总结，再由该模型合并，绝不使用旧的截断脚本冒充模型摘要。

模型生成七节事实交接；来源会话、来源哈希、真实模型和最近三轮用户原话附在摘要中。失败保留原会话，只有成功摘要才创建续接会话。原生手动压缩必须有实际完成事件，否则走已验证的模型压缩链路，不能把“触发”当“完成”。

当前安装的2.1.97不识别CLAUDE_CODE_MAX_CONTEXT_TOKENS；其CLI源码对无1m后缀的自定义模型采用200000默认窗口，不能把配置数字称作已扩容。本候选对扩展窗口尚未验证的路线按200000保守预算，保留原参数并明确提示，没有修改模型ID或声称已启用百万上下文。未来扩展窗口必须另行用真实CLI和提供商验收，不在本次自动升级二进制。

输出预算最多占保守窗口的四分之一，不重写用户存储配置，并在运行过程说明安全限制；本次异常参数组合实际输出预算上限50000，宿主安全输入预算135000，主动压缩阈值121500，而不是原先约11059。自动压缩窗口不能大于安全输入预算。stdin 已消除 argv 限制，取消把140KB当模型上下文上限。实际超过安全预算时才必须先压缩；可选压缩失败不会阻止预算内的正常发送。真实模型服务彻底不可用时仍不能承诺生成摘要或继续请求，不伪造成功。

## 验证与验收

新增九项 Node 行为测试覆盖工具隔离、无损分片、响应有效性、故障重试、较小分片恢复、模型合并、原话保留、原会话不变和取消。新增四项 JVM 预算测试在云端执行。

使用设备当前已安装 Claude 2.1.97 和 MiniMax-M3，从失败时的真实十一条消息运行相同生产 worker。全文压缩与新的模型续接理解请求成功；原会话文件SHA256前后均为ba090e490c2b96a717a1cf3966b0a6fca9fee8bdee97a28e4c1cf6d4efac3a7e。真实调用两次，压缩工具数零，最近三轮原话、M5 Max 128GB设备纠正、最新附件日期和待处理搜索任务保留。分片真模型验证另行记录在本地诊断目录。

用户覆盖 v363 后不需要安装或更新 Claude，也不需要新建任务。打开原 Claude 会话继续发送原请求，参数组合不得再次触发虚假的短上下文硬限制；手动压缩应产出真实七节交接、原话与来源标识，然后可继续用原有工具处理待完成任务。重启后原会话和续接都应可见，Codex和其他智能体仍能正常收发消息、调用工具及保存历史。此版本修复真实模型压缩与预算，百万上下文并未被本次验收为可用功能。
